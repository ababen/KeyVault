# KeyVault

Native macOS SwiftUI app for storing API keys, OAuth credentials, and multi-field developer secrets on-device, encrypted per field with AES-256-GCM. Local-only — no network, no sync.

## Stack

- **Swift 5.9**, SwiftUI + **SwiftData** (`@Model`), CryptoKit, CommonCrypto (PBKDF2), AppKit, Security, UserNotifications
- **macOS 14.0+** deployment target, Xcode 15+
- Project generated by **XcodeGen** from `project.yml` (min xcodegen 2.38.0)
- Bundle ID `com.keyvault305.app` · Team `T47L6TGCS8` · Scheme/target `KeyVault` · Test target `KeyVaultTests`
- No SwiftPM/CocoaPods dependencies — Apple frameworks only

## Build / Test / Run

```bash
brew install xcodegen          # required, not vendored
./setup.sh                     # runs `xcodegen generate` then opens the project
xcodegen generate              # regenerate only (no Xcode launch)

xcodebuild -project KeyVault.xcodeproj -scheme KeyVault -configuration Debug build
xcodebuild test -project KeyVault.xcodeproj -scheme KeyVault -destination 'platform=macOS'
```

Run the app with ⌘R in Xcode on a real Mac — Touch ID and Keychain access do not work in a simulator.

**Constraints for headless/cloud sessions:** full Xcode is required. In a bare environment `xcodebuild` fails (`active developer directory '/Library/Developer/CommandLineTools'`) and `xcodegen` is not on PATH, so the project cannot be generated, built, or run there. Restrict work to source edits, and don't claim a build was verified.

No shared schemes are committed (`KeyVault.xcodeproj/xcshareddata/xcschemes` is empty) — Xcode auto-creates the `KeyVault` user scheme on first open. If `-scheme KeyVault` isn't found, use `-target KeyVault`.

### Distribution (branch: `release/testflight-setup`)

`ExportOptions.plist` is configured for `app-store-connect` export, destination `export`, team `T47L6TGCS8`, automatic signing. Existing artifacts in `build/` (`KeyVault.xcarchive`, `export/KeyVault.pkg`, v1.0.0 build 1, x86_64 + arm64) were produced with:

```bash
xcodebuild archive -project KeyVault.xcodeproj -scheme KeyVault -archivePath build/KeyVault.xcarchive
xcodebuild -exportArchive -archivePath build/KeyVault.xcarchive \
  -exportOptionsPlist ExportOptions.plist -exportPath build/export
```

Both `build/` and `ExportOptions.plist` are gitignored — a fresh clone will not have `ExportOptions.plist`. Bump `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` in `project.yml`, not in Xcode.

## Layout

```
project.yml                    # SOURCE OF TRUTH for the Xcode project
setup.sh                       # xcodegen generate + open
KeyVault/
  App/KeyVaultApp.swift        # @main, ModelContainer schema, ⌘N / ⇧⌘L commands, ContentView router
  App/AppState.swift           # @MainActor lock state + live SymmetricKey; setup/unlock/lock
  Models/                      # Entry, SecureField.swift (class VaultSecureField), EntryTemplate, Agent, AgentGrant
  Security/                    # VaultCrypto, KeyDerivation, KeychainManager, AutoLock
  Services/                    # VaultService (CRUD+crypto), ExportService, ExpirationMonitor
  Utilities/                   # ClipboardManager (30s auto-clear), DateFormatting
  Views/                       # MainView (3-column) + Sidebar/ EntryList/ EntryDetail/ EntryEditor/ Unlock/
KeyVaultTests/VaultCryptoTests.swift   # VaultCryptoTests + KeyDerivationTests (only test file)
```

27 Swift files total. `ContentView` lives inside `App/KeyVaultApp.swift`, not its own file.

## Conventions & gotchas

- **Never hand-edit `KeyVault.xcodeproj`** — it is generated and will be overwritten. Change `project.yml` instead. Sources are declared as the `KeyVault` directory, so new `.swift` files under it are picked up automatically with no project edit.
- **`xcodegen generate` also rewrites `KeyVault/KeyVault.entitlements`** from `project.yml`'s `entitlements.properties` (app-sandbox, user-selected read-write). Edit entitlements in `project.yml` or they will be reverted.
- **`VaultSecureField` is the class name; the file is `Models/SecureField.swift`** — named to avoid colliding with SwiftUI's `SecureField`. (README's structure section says `VaultSecureField.swift` and is stale; it also refers to a `keychain-access-groups` entitlement that doesn't exist in the file.)
- **Crypto shape:** `VaultCrypto` stores AES-GCM `ciphertext`, `nonce`, and `authTag` as three separate `Data` properties — not `sealed.combined`. Decryption reassembles the `SealedBox` from all three; any change to one must preserve the others.
- **Always mutate field values through `VaultService`** (`addField` / `updateFieldValue`), which encrypts and stamps `entry.updatedAt`. Writing `field.encryptedValue` directly bypasses encryption.
- **`VaultService` / `ExportService` are constructed ad hoc per view** from `appState.encryptionKey`, which is `nil` while locked — views guard on it and no-op. There is no injected singleton.
- **Touch ID is not driven by `LocalAuthentication`** — there is no `LAContext` anywhere. Biometrics come from the Keychain item's `.userPresence` access control plus `kSecUseOperationPrompt` in `KeychainManager.retrieveKey()`.
- **Keychain layout:** service `com.keyvault.encryption-key`, accounts `vault-key` (derived 256-bit key, userPresence-protected), `vault-salt`, `vault-verification` (SHA-256 of derived key). `isFirstLaunch` is derived from `KeychainManager.keyExists()`, so clearing the Keychain resets the app to setup — but the SwiftData store still holds entries encrypted under the old key.
- **`ExportService` and `ExpirationMonitor` are implemented but unreferenced** — no view or app-lifecycle code calls them, and `ExpirationMonitor.requestPermissions()` is never invoked. The README lists encrypted export/import and expiry notifications as features; they have no UI entry point yet.
- **Search only covers `name`, `provider`, `tags`, `notes`** (`EntryListView`) — encrypted field values are not searchable.
- **⌘N is bound twice**: the `CommandGroup(replacing: .newItem)` menu item posts the `.newEntry` notification, and `MainView`'s toolbar button separately declares `.keyboardShortcut("n")`. Both open the editor; account for this when touching either.
- **Auto-lock is hardcoded to 5 minutes** at `AppState.init` (`AutoLock(timeoutMinutes: 5)`); `updateTimeout(minutes:)` exists but nothing calls it. `AutoLock` also locks on `screensDidSleep` and `com.apple.screenIsLocked`.
- **Tests cover crypto only** — round-trip, wrong-key, nonce uniqueness, unicode, PBKDF2 determinism, verification hash. No Keychain or SwiftData tests (both need a host app / real device).
- The app is sandboxed; file export/import relies on `com.apple.security.files.user-selected.read-write`, so paths must come from an `NSOpenPanel`/`NSSavePanel`.
- `DEVELOPMENT_TEAM` is hardcoded in `project.yml`; a different signer must change it there.
